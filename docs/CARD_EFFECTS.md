# Card data and effects (for the TF3 Cards mod and card editors)

How the game stores one card's behaviour, and what the tools in this repository can write. Everything here was checked against Tag Force 1 (EU) running in the recompilation.

## The card map

`python -I tools/game/mapa_cartas.py [out.json]` builds one JSON file with every card of Tag Force 1 and Tag Force 3:

* cards are matched across the games by the 8-digit passcode (`CARD_Pass`), by name when the passcode is 0;
* per card: ids in both games, name, passcode, category, kind (monster / spell / trap), ATK, DEF, level, both texts and the effect record of each game;
* `handlers_tf3`: for every TF3 handler, the TF1 handler learnt from the cards both games share (`mapped` / `conflict` / `unmapped`);
* `donor`: the shared card with an identical record whose text reads most like the card's (a hint, not a guarantee);
* `ids_novos()` lists the cards that exist only in TF3.

The file holds game text, so it is written to `gen/` and kept out of git.

## How a card works in a duel

1. **Data**: `CARD_Prop` (stats, category, type, attribute), `CARD_Pass`, `CARD_Genre`, names and descriptions, all in `cardinfo_<lang>.ehp`.
2. **Effect record**: six words `{card id, 5 handler pointers}` in four tables of `libduel_eng` (found by hook `09eb4574`). Only about 1500 of the 2480 cards have one. A record names a *generic* handler: a step machine that returns the next step number and calls engine primitives. Two cards with the same handler can still behave differently.
3. **Per-card code**: the card-specific part lives either in a function table keyed by id (the candidate scan, `09f76818`, 364 entries) or in chains of `if (id == N)` inside shared functions (passive monster effects, stat changes, equip rules, costs). The chains cannot be extended with data.

## Effects in data (TF3 Cards)

A new card borrows the record of a card that plays the same way (`like`) and lists which cards its effect may pick. The plugin replaces the candidate scan of the new card with a lookup in that list.

`tools/mods/tf3_efeitos.json` (hand written, wins) and `tf3_efeitos_auto.json` (generated by `tf3_efeitos_texto.py` from the card text):

```json
{ "7460": { "like": 5328, "zone": "deck",
            "filter": { "monster": true, "level_max": 4, "name_has": "Gladiator Beast" } } }
```

| zone | effect | donor (`like`) |
|---|---|---|
| `deck` | add 1 card from the Deck to the hand | 5328 Reinforcement of the Army |
| `grave` | add 1 card from the Graveyard to the hand | 5330 The Warrior Returning Alive |
| `grave_summon` | Special Summon from the Graveyard (continuous trap) | 4989 Call of the Haunted |
| `hand` | Special Summon from the hand | 6572 Magnet Circle LV2 |

Filter keys: `monster`, `normal`, `level_min`, `level_max`, `type`, `attribute`, `atk_min`, `atk_max`, `def_min`, `def_max`, `name_has`, `name_is`.
`tools/mods/tf3_efeitos_param.py` turns a filter into the sorted id set stored in `effects.bin`; the plugin side is described in `plugins/src/TF3Cards/README.md`.

`python -I tools/mods/tf3_audit.py` builds a local review queue in `gen/tf3_audit.json`. A card with a rule may still have other unimplemented clauses; a suggested donor is a lead for investigation, not a verified effect. The report contains game text and stays outside the repository.

## Triggers

The game decides when an effect starts in one predicate (`09f30ddc`), a chain of `id == N` branches. A spec entry with `"trigger_like": <TF1 card id>` makes the game answer that predicate as if the card were the donor
(for example `"trigger_like": 4054` = "when this card is sent from the field to the Graveyard", like Sangan). The effect itself still comes from `like` (the record) and `zone`/`filter`:

```json
{ "7892": { "like": 4054, "trigger_like": 4054, "zone": "deck",
            "filter": { "monster": true, "type": "plant", "def_max": 1000 } } }
```

Checked in a duel: Botanical Girl destroyed by Dark Hole opens the Deck list with only Plant monsters of 1000 or less DEF and adds the chosen card to the hand.

### Summon triggers

A spec entry with `"trigger_event": "summon"` (set by `tf3_efeitos_gatilho.py` for "When this card is Normal Summoned, ..." texts) also holds the donor alias while the game scans the events of a finished action (`09e89110`, which reads the acting card's id from the action record at `09f788a4`). With `"trigger_like": 6151` (Green Gadget) the card prompts "Activate the effect of ...?" after a Normal Summon and the data effect runs. Checked in a duel: Genex Power Planner added a Level 3 "Genex" monster from the Deck to the hand.

FLIP effects (donor 5769) are set up the same way but do not fire yet when the card is flipped by an attack; the game queues that event along a different path (not an id chain). Not working.

## Draw and life point effects

`"draw": {"self": N, "opp": N}` and `"lp": {"self": N, "opp": N}` (positive = gain, negative = damage) give a card the numbers of the game's one-step draw and life point handlers; the game fixes these numbers per card id inside the handlers, so the plugin reads them from `amount.bin` instead:

```json
{ "7235": { "like": 4844, "draw": { "opp": 2 } },
  "7234": { "like": 4353, "lp": { "opp": 3000 } } }
```

Either record may carry `"per": {"side": "own|opp|both", "filter": {...}, "distinct": true}`: the numbers are multiplied by how many face-up monsters of that side match the filter (`distinct` counts different card ids only), e.g. `"7619": {"like": 4844, "draw": {"self": 1, "per": {"side": "own", "filter": {"monster": true, "name_has": "Neo-Spacian"}, "distinct": true}}}` (Space Gift). The rules are a `TF3M` trailer of `amount.bin`. Checked in a duel with an opponent-side filter: +1000 life points and 1 card drawn for one opposing monster.

A draw record may also carry `"discard": {"count": N, "filter": {...}}`, a cost paid when the effect resolves: N matching cards of the controller's hand are sent to the Graveyard (engine steps `09f4be50` + `09f4bff8`), then the cards are drawn. With too few matching cards nothing is discarded or drawn, and the Spell is still used up (the activation itself is not blocked). Used by Trade-In (`{"like": 4844, "draw": {"self": 2, "discard": {"count": 1, "filter": {"monster": true, "level_min": 8, "level_max": 8}}}}`) and Destiny Draw. Checked in a duel with `tf3_lote.py --hand`: deck -2, hand card gone; without a matching card the deck is unchanged. The rules are a `TF3C` trailer of `amount.bin`.

`"discard"` accepts `"to": "deck"` (the cost cards go back to the Deck instead of the Graveyard: Gladiator Beast's Respite, 2 cards then draw 3). A draw record may also carry `"mill": {"count": N, "filter": {...}}`: after the draw, the first N matching cards of the controller's Deck are sent to the Graveyard (trailer `TF3X`). Solar Recharge is discard 1 Lightsworn monster, draw 2, mill 2 (no filter); Snake Rain is discard 1 card (any), draw 0, mill 4 Reptile monsters. Checked in duels: the Deck count drops by the expected amount (7311 -1, 7625 -4, 7166 -4 with Reptiles placed in the Deck).

`"destroy"` with `"cond": {"kind": "target", "filter": {...}}` and `"zones": "monster"` plays "Destroy 1 face-up monster that matches the filter" (donor Dark Hole 4342, `"side": "both"`): only matching face-up monsters count as targets and the first one found is destroyed; with no match the card cannot be activated. `category_in` in a filter selects card categories (2, 3 = Fusion, 4, 5 = Ritual). Checked in a duel with a Spell as host: the opponent's monster is destroyed, and a filter that matches nothing leaves it alone. Trap hosts (Anti-Fusion Device, Ritual Sealing) still need a Trap donor with a free activation.

A stat rule's `cond` may count a Graveyard instead of the field: `"cond": {"side": "own|opp|any", "zone": "grave", "per": true, "filter": {...}}` ("gains 500 ATK for each Reptile-Type monster in your Graveyard"). Used by Ally of Justice - Light Gazer, Vennominon, Vennominaga, Darknight Parshath and Colossal Fighter; only their ATK clause is implemented (their other clauses are not). `tools/test/tf3_stat_batch.py` checks dozens of stat rules in one duel session (about a minute): the delta of the card's ATK / DEF with its source enabled versus disabled, with seeded Graveyards.

Equip rules (`"scope": "equip"`) accept the same `cond` / `per`, counted relative to the equip card's controller: Fighting Spirit is `{"scope": "equip", "atk": 300, "cond": {"side": "opp", "per": true, "filter": {"monster": true}}}` (+300 per opposing monster; its "destroy this card instead" clause is not implemented). Assault Armor gives +300 to Warriors (its "only monster you control" restriction and double attack are not implemented).

`"to": "deck"` sends the picked cards back to the Deck instead of the hand and `"then_draw": N` (0-7) draws afterwards: Gladiator's Return is `{"like": 5330, "zone": "grave", "count": 3, "to": "deck", "then_draw": 1, "filter": {...}}` (the Deck is not shuffled; the extra cards are picked automatically). Checked in a duel with a Spell host: deck +3 -1 and hand unchanged. Psychic Overload (Trap, same effect with 2 draws) was checked with the `armadilha_sel` script: set, opponent attacks, Activate, pick from the list: deck +3 -2, hand +2. Note the chain prompt only appears when the donor finds candidates, so seed the Graveyard with `--grave` (there are no original Psychic monsters; use the ids of TF3 cards).

Psychic Rejuvenation is `{"like": 4986, "lp": {"self": 1000, "per": {"side": "own", "filter": {...}}}}` (donor Gift of The Mystical Elf, a Trap without conditions); checked as a Trap in the attack test: +1000 per counted monster (opponent side used for the test).

`"count": N` on a `deck` / `grave` effect moves N cards to the hand instead of 1: the game asks for the first card as usual and the plugin repeats its own move step (09f3aa3c, phase 1; source reference u16 at 09f788c2, destination at 09f788c4) for the next N-1 matching cards of the zone, in zone order. Checked in duels: Recurring Nightmare, Recycling Batteries and Quick Charger each end with +2 cards in hand (donor 5330).

The `like` donors are Pot of Greed (draw) and Tremendous Fire (life points). A trigger spec may combine any trigger donor with these records: while the aliased trigger runs, the record lookup uses the card's own `like` instead of the trigger donor's. `tools/mods/tf3_efeitos_gatilho.py` writes them for texts such as "When this card is destroyed by battle and sent to the Graveyard, draw 1 card" / "both players take 500 damage".
Checked in a duel: Blizzed (draw 1) and Abaki (both players 2000 → 1500).

"When this card inflicts Battle Damage to your opponent, draw 1 card" works with `"like": 4226, "trigger_like": 4226, "trigger_event": "battle"` (Masked Sorcerer): while the game resolves battle damage (09f28de8) the plugin shows it the donor's id. Checked in a duel: a new 2000 ATK card drew a card for its controller after hitting the opponent.

"When this card destroys an opponent's monster by battle and sends it to the Graveyard, you can Special Summon ... from your Deck" works with `"like": 6479, "trigger_like": 6479, "trigger_event": "battle"` plus `zone` / `filter` (donor Hydrogeddon). Checked in a duel: after the kill the game asks "Activate the effect of <new card>?" and the chosen monster arrives from the Deck. A trigger donor only works with a record of its own family (a draw record from another trigger does not start).

Not wired yet: "Special Summoned from the Graveyard".

## "Destroy all" effects

`"destroy": {"side": "own|opp|both", "zones": "monster|st|all", "cond": {...}}` makes a card borrow the record of Dark Hole (`"like": 4342`) and narrows what the game's destroy driver may hit. `cond` is the "Activate only when ..." part, checked while the game asks whether the card can be activated: `{"kind": "opp_monsters_full"}`, `{"kind": "opp_st_full"}` or `{"kind": "controls", "n": 3, "filter": {...}}` (N face-up monsters matching the filter). The numbers go to `destroy.bin`.

```json
{ "6899": { "like": 4342, "destroy": { "side": "opp", "zones": "monster", "cond": { "kind": "opp_monsters_full" } } } }
```

Checked in a duel: Flash of the Forbidden Spell cannot be activated while the opponent has free monster zones, and with the condition off it destroys the opponent's monsters; Short Circuit (condition off) destroys the opponent's monster. Destroying Spell / Trap cards through the same rule is not checked yet.

Attack traps borrow Mirror Force (`"like": 4887`): the game's own "opponent declared an attack" test (09ed5870) starts the trap and the donor's filter destroys the Attack Position monsters. `{"kind": "opp_attack_monsters", "n": 3}` adds "while they control 3 or more Attack Position monsters" (Radiant Mirror Force, 7137), evaluated inside that test. Checked in a duel: with 2 attackers and N = 3 the trap is not offered; with N = 1 it is offered and clears the opponent's monsters.

## Passive bonuses of continuous Spells

`tools/mods/tf3_stats.json` rules take `"source": "st"` when the card is a continuous Spell: the rule works while the card is face-up in a Spell / Trap or Field Spell zone of either side (scope `own` / `opp` / `all` is relative to its controller). Sources must have their effects enabled. Spell bonuses also obey the target's native Spell-immunity mask. `"per_level": true` multiplies the bonus by the target's current level, so Burden of the Mighty follows level changes.

```json
{ "7457": { "scope": "all", "source": "st", "atk": -500, "def": 400, "target": { "monster": true, "attribute": "earth" } } }
```

Checked in a duel: Burden of the Mighty took 400 ATK from a Level 4 opponent monster (1400 -> 1000). Acidic Downpour and Wetlands use the same path (not duelled separately).

## Equip Spells

`tools/mods/tf3_efeitos_equip.py` writes the borrowed record and a `"scope": "equip"` stat rule for texts such as "Equip only to a DARK monster. It gains 400 ATK." Filtered equip rules also restrict selection through the native common equip-target predicate. This covers printed type, attribute and name restrictions, including Crystal Beast and Gladiator Beast names. Board transformations of those properties still need verification. Extra clauses are implemented individually: Ancient Gear Tank's destruction damage and Lucky Iron Axe's opponent-effect draw are supported; several return/replacement clauses remain incomplete. An equip rule may also specify `"level": 1`; Synchro Boost increases the equipped monster's level as well as its ATK. These level bonuses use an optional `LVL1` trailer in `stat.bin`, read by the updated plugin. `tools/test/tf3_verify_equips.py` checks ordinary valid, invalid and face-down targets on both sides.

`tools/test/tf3_verify_stats.py` checks controlled field fixtures through the real duel engine using the opt-in `tools/test/tf3_probe.cpp` plugin. It tests stat clauses and source disabling/removal; it does not certify every clause or interaction of those cards.

`"attack_protect": {"filter": {"monster": true, "attribute": "wind"}, "exclude": "self"}` prevents selecting the source as an attack target while another matching face-up monster is controlled. `exclude: "same_name"` excludes every copy of the source, as Freya requires. Type and attribute conditions use the engine's current values. `"control_lock": true` prevents changing control of the face-up source while its effect is enabled. These use optional `ATP1` and `CTL1` trailers in `stat.bin`. `tools/test/tf3_verify_attacks.py` compares protection and control behavior with native TF1 cards.

FLIP classification is borrowed from the trigger donor as well as its effect record. This allows Worm Cartaros to enter the native FLIP path when attacked face-down. `tools/test/tf3_verify_flip.py` checks classification and a complete battle-triggered search in an isolated duel.

Equipment stat and level bonuses follow the native equipment relationship list on the target monster. The source may be on either side of the field; spell immunity is relative to that source's controller. An unattached equip grants no bonus. `tools/test/tf3_verify_stats.py` covers both controllers and ignores the unrelated summon-turn field. The event integration tool also checks a normally activated Lucky Iron Axe's 500 ATK bonus before destruction.

Legendary Ebon Steed replaces destruction through the native marking/removal mechanism and the separate battle staging path. A protecting equip already marked for removal cannot replace another destruction. Multiple Steeds are consumed separately; unrelated equipment is preserved. `tools/test/tf3_verify_replacement.py` covers controlled removal causes, simultaneous removal and a complete natural battle. `tools/test/tf3_verify_parallel.py` runs eight independent engine suites with separate execution packages, saves, caches and logs.

`"trigger_condition"` supports `destroyed`, `by_effect`, `opponent_effect` and `face_up`. Conditions use the native removal reason and suppress only the matching source event. `"trigger_record_like"` can borrow a different record for the pending trigger while preserving the normal activation record (Lucky Iron Axe equips like Axe of Despair and resolves its Graveyard trigger with a draw record). These use optional `TGC1` and `TGR1` trailers in `trigger.bin`. `tools/test/tf3_verify_equip_events.py` checks complete resolution and negative causes through opt-in native removal actions in isolated duels; the opponent cause bit is relative to the affected card's controller.

Sword of Dark Rites uses `"trigger_condition": {"equipped_tributed": true}` to match the engine's tribute reason and the attached equip's instance token. Its Graveyard effect borrows Elma's return routine with a private record copy that removes the optional-activation callback; normal activation and native records are unchanged. `tools/test/tf3_verify_sword.py --case natural` checks a real Tribute Summon and return to hand. Non-destructive sends, destruction and banishment are separate negative cases.

Battle Gladius uses `"equipped_to_deck": true` instead. The departing monster must have the equip controller's side of the field as its origin. Its return uses the same mandatory native routine. `tools/test/tf3_verify_sword.py --gladius --case deck` and the `doubledeck`, `opposing`, `hand`, `destroy`, `send` and `banish` cases check this condition through controlled engine actions.

## Known limits

* The first two new ids (6958, 6959) cannot be Normal Summoned as monsters (the card menu only offers "Show Details"); keep Spell/Trap cards there (`tools/mods/tf3_gids.txt` does).
* While a trigger runs, the game shows the donor's name and text in the selection panel.
* Goblin Decoy Squad's `"after_attack_defense": true` trigger flag reuses native Goblin Attack Force markers. Position changes and lock expiry are covered by `tools/test/tf3_verify_position.py`; broader interactions still require verification. Splendid Venus's protection for Spell and Trap effects is not implemented.
* Pending trigger sources are tracked by donor, controller and instance token, including deferred replay. Controlled queue/transfer tests cover multiple imported sources and the native donor. Wider simultaneous natural-play interactions still need verification. `TF3_EVENT_IDS=0` selects the legacy comparison path.

## Adding a new kind of effect

1. Find a TF1 card that plays the same way and read its record (`tools/game/tf3_efeitos.py`, `mapa_cartas.py`).
2. Find what the card-specific part is: a scan function (table `09f76818`), a chain of ids, or something else. Hook point lists are in `docs/HOOKS.md`.
3. Replace only that part for the new ids and keep the donor's record for everything else.
4. Test in a duel with `tools/test/tf.py` (`TF3_FORCE_CARDS` forces TF3 card ids into the opening hand).


Grave Squirmer is `{"like": 5484, "trigger_like": 5484}` (donor Newdoria): after it is destroyed by battle the game destroys 1 monster on the field, as for Newdoria. Its text says "1 card", so Spell / Trap Cards cannot be chosen (partial). The destroy rules of `destroy.bin` only apply to the three "destroy all" filters of Dark Hole / Raigeki / Heavy Storm: a trigger monster destroys through its donor's own target filter, so it destroys what the donor destroys (a FLIP monster that borrows 4-Starred Ladybug of Doom destroys Level 4 monsters, not what its text says).
`tools/test/tf3_flip_kinds.py` prints the game's FLIP classification (1 = FLIP) of card ids in one session; every TF1 FLIP monster tried (Man-Eater Bug, Cyber Jar, Old Vindictive Magician, ...) answers 1. `tf3_lote.py --rot virar` Sets the first hand card (a monster), ends the turn and lets the opponent attack it.
